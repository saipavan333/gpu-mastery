Softmax Stability Explorer

Softmax turns a vector of scores into probabilities, and it sits inside every attention layer of every transformer. Written the obvious way, it silently blows up on large scores — exp overflows and the whole thing becomes NaN. The fix is one line that every serious implementation uses (and that FlashAttention builds on). Type in some logits and watch the naive version break while the stable version stays exact.

Edit any value. fp32's exp overflows around x ≈ 88.7 (exp ≈ 3.4×10³⁸); fp64 (what this page computes in) overflows around x ≈ 709. Either way, the naive form is a time bomb.

Naive softmax

p_i = exp(x_i) / Σ exp(x_j)

Stable softmax — subtract the max first

m = max(x); p_i = exp(x_i − m) / Σ exp(x_j − m)

How to read it

Both formulas are mathematically identical — subtracting the max m multiplies every term, top and bottom, by exp(−m), which cancels. So the stable version changes nothing about the answer; it only changes what the hardware has to compute. The naive form evaluates exp(x_i) directly, and for a large score that number is astronomically big — past the largest value the float type can hold, it becomes inf, and inf/inf is NaN. The stable form first shifts every score so the biggest is 0: now the largest exp is exactly exp(0) = 1, everything else is smaller, and nothing can overflow. Same probabilities, no explosion.

This is not a toy concern. Attention scores in a large model routinely reach magnitudes that overflow fp16 (whose exp overflows near x ≈ 11) and even fp32, so the max-subtraction is mandatory in production. FlashAttention — Track A's centerpiece — pushes the idea further: it computes attention in tiles that never fit the whole score row in memory, keeping a running max and rescaling partial sums as it goes (an "online softmax"), so it gets the stable result without ever materializing the full attention matrix. Understanding why the max-subtraction is exact (this lab) is the first step to understanding why FlashAttention is both correct and fast. It also echoes Lesson 1.8's theme: floating point has limits, and numerically-aware code is the difference between a model that trains and one that fills with NaN.

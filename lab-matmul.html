WebGPU Matmul Lab — the tiling win, live on your GPU

Two kernels compute the exact same matrix product on your GPU: naive (every thread re-reads its row and column straight from global memory) and tiled (every thread first stages a block into fast on-chip shared memory and reuses it). Same math, same answer — the only difference is how many times the GPU has to go to memory. That gap is lesson 5.5's whole point, made visible instead of asserted.

How to read it

Both kernels do identical arithmetic — same 2·N³ multiply-adds, same result. The naive kernel's arithmetic intensity is fixed and low: each thread streams 2·N values in from global memory to do 2·N flops, so it never rises above roughly 1 FLOP/byte-ish territory regardless of N — deep in the memory-bound region of the Roofline Explorer. The tiled kernel loads each TILE×TILE block into var<workgroup> shared memory once, then every thread in the workgroup reuses it TILE times before moving to the next block — that single change multiplies the arithmetic intensity by roughly TILE (16 here), which is usually enough to walk the kernel from the memory roof toward the compute roof. Bigger N makes the gap more visible: more reuse opportunities for tiling to exploit, so try 1024 or 2048 after the default.

The correctness check doesn't recompute the full N×N output on the CPU (for N=2048 that's 17 billion operations — too slow for a browser tab). Instead it spot-checks 12 random output elements against a direct CPU dot product at those exact indices. If both kernels agree with the CPU oracle at every sampled point, you can trust the rest — this is the same "fixture, not full replay" verification doctrine from M2 L6.

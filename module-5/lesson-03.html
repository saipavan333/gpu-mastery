Memory Management — two worlds, one bridge, your discipline

3.5 made you the garbage collector; today you manage TWO heaps separated by 4.6's bridge. The rules are ones you already keep — one owner, exact frees, bytes-not-elements — plus one new law: know which world every pointer belongs to.

Concept

Two address spaces, one pointer type

float *h_x = (float*)malloc(bytes);          // HOST heap (3.5, unchanged)
float *d_x;
CUDA_CHECK(cudaMalloc(&d_x, bytes));         // DEVICE heap — 3.3's & pattern, at last
h_x[0] = 1.0f;            // ✓
d_x[0] = 1.0f;            // ✗ host-side deref of a device address: segfault (3.8)
kernel<<<g,b>>>(h_x,…);   // ✗ compiles clean, garbage/crash on device — the
                          //   worst kind of wrong: type-correct, world-wrong

The lifecycle: the 3.5 dance, six steps

CUDA_CHECK(cudaMalloc(&d_x, n * sizeof *d_x));                 // 3.5's sizeof idiom survives
CUDA_CHECK(cudaMemcpy(d_x, h_x, n*sizeof *d_x, cudaMemcpyHostToDevice));
saxpy<<<grid, block>>>(n, a, d_x, d_y);
CUDA_CHECK(cudaMemcpy(h_y, d_y, n*sizeof *d_y, cudaMemcpyDeviceToHost));  // implicit sync!
CUDA_CHECK(cudaFree(d_x));                                     // one owner, exactly once

Asynchrony: the CPU runs ahead

Three consequences, each a bug you'll now never write: (1) CPU timers around a bare launch measure the enqueue (~5 µs), not the kernel (5.9's events fix); (2) reading results before a sync reads stale bytes (the plain D2H memcpy's implicit sync is why the naive flow works at all); (3) errors surface at the next checked call, lines after the crime (5.4's subject). The implicit-sync roster: plain cudaMemcpy, cudaDeviceSynchronize, cudaFree, event/stream syncs — everything else queues.

Managed memory: the honest tool

cudaMallocManaged(&x, bytes);      // one pointer, both worlds — pages migrate on touch
// 5.2 used it to defer THIS lesson. The 4.5 §4 ledger stands:
//   prototyping: gold  ·  phase-separated access: fine (+ cudaMemPrefetchAsync)
//   hot-loop ping-pong: page-fault storms at bridge latency (4.6 §3 priced them)
// Course policy: managed for exploration, explicit for anything measured.

Worked example

Task: The reusable harness — gpu_buffer.cuh, the RAII wrapper 3.7 Ex.1 rehearsed (DeviceBufferSim, promoted to the real thing), plus the round-trip test that certifies the plumbing.

// gpu_buffer.cuh — 3.7's RAII + 3.3's contracts + 5.4's checks, one header
template <typename T>
struct DeviceBuffer {
    T *d = nullptr; size_t n = 0;
    explicit DeviceBuffer(size_t n_) : n(n_) {
        CUDA_CHECK(cudaMalloc(&d, n * sizeof(T)));
    }
    ~DeviceBuffer() { cudaFree(d); }                       // dtor: can't forget (3.7)
    DeviceBuffer(const DeviceBuffer&) = delete;             // no copies: no double-free
    DeviceBuffer& operator=(const DeviceBuffer&) = delete;
    void up(const T *h)   { CUDA_CHECK(cudaMemcpy(d, h, n*sizeof(T), cudaMemcpyHostToDevice)); }
    void down(T *h) const { CUDA_CHECK(cudaMemcpy(h, d, n*sizeof(T), cudaMemcpyDeviceToHost)); }
};

// round_trip test: up(pattern) → identity kernel → down → EXACT compare.
// Certifies: both copies, the kernel path, alignment, sizes — the plumbing
// fixture every later kernel builds on (M2 L6 layer 5: contract tests).

Why each line is old news: the dtor is 3.7's RAII diagram (every exit path frees); deleted copies are Ex.1's no-double-free law; up/down centralize direction (the #1 memcpy typo: swapped dst/src — one place to get it right); sizeof(T)·n is 3.5's bytes-not-elements idiom. Decision made: the destructor calls cudaFree UNCHECKED — dtors shouldn't exit() mid-unwind (3.7 §5's exceptions note); instead the harness calls a final CUDA_CHECK(cudaDeviceSynchronize()) so sticky errors surface before teardown. Small print like this is what "production-shaped" means, and you had every piece by 3.7.

Key points

  • Host and device pointers share a type but not a world — h_/d_ naming is your type system; crossing worlds is cudaMemcpy's job alone.
  • The lifecycle is 3.5's dance with a bridge in it: malloc/memcpy-up/launch/memcpy-down/free, bytes = n·sizeof*p, cleanup path with free(NULL)-safe teardown.
  • Launches are async: implicit syncs (plain memcpy, deviceSync, free) are load-bearing; everything else queues — timers and error checks must respect this.
  • cudaMemcpy direction enums are checked at runtime, but swapped dst/src compiles AND runs — centralize copies (up/down methods) so the typo has one home.
  • Managed memory: prototype freely, prefetch when phases are known, never ping-pong in hot loops — 4.5/4.6's economics decide, not convenience.
  • RAII device buffers (3.7's pattern) end the leak/double-free class on day one — the capstone's harness is this worked example, unchanged.

Quiz

1. cudaMemcpy(h_y, d_y, n*sizeof(float), cudaMemcpyDeviceToHost) after a kernel launch returns correct data WITHOUT any explicit synchronize. Why — and which two changes would break that safety?
Stream order is the guarantee (the async diagram's timeline): same-stream operations serialize. Async variants and cross-stream launches remove exactly that guarantee — which is why 5.9 pairs them with events. The pointer-dependency option is seductive and false: CUDA tracks STREAMS, not data flow — you are the dependency tracker (M2 L3's explicit-state philosophy, at driver level).
2. A 2 GB managed-memory training prototype runs fine; adding a per-step printf("%f", loss_tensor[0]) on the HOST makes each step 400 ms slower. Mechanism, and the two fixes in cost order?
One innocent host read = two page migrations per step (the ledger 4.5 §4 wrote). The tiny-memcpy fix respects the topology (8 bytes cross, not pages); the batch-N fix respects the toll count (4.6 §3). Managed memory didn't lie — it silently obeyed a topology you stopped watching. This exact bug, in PyTorch clothing (.item() per step), is 4.6 P5's grep list — now you've seen its CUDA skeleton.

Go deeper — the rest of the memory API, honestly ranked

1. The allocation family (when each earns its place)

cudaMalloc            the default: device heap, 256-B aligned (4.5's guarantee)
cudaMallocHost        pinned host: transfer buffers, async-capable (Ex.2's 2×)
cudaMallocManaged     one pointer: prototypes + phase-separated apps (+prefetch)
cudaMallocAsync       stream-ordered pool allocation: malloc/free INSIDE hot loops
                      without the sync+cost of cudaMalloc (3.5 §1's arena, official) —
                      the modern default for frameworks; meet it properly in Track A
cudaMemset(d, 0, bytes)   device-side zeroing (calloc's cousin — same byte caveats 3.5 §5)

2. cudaMemcpy2D and strided reality

cudaMemcpy2D(dst, dpitch, src, spitch, width_bytes, height, kind);
// copies a WxH rectangle out of larger rows — pitch = allocated row stride.
// Exists because sub-image copies from an (H, W) buffer aren't contiguous
// (M2 L5's views taught you why). cudaMallocPitch pads rows to alignment —
// the LDA of 4.2 P3, as an allocator. For this course: flat + full-row copies
// keep life simple; know 2D exists so library signatures read instantly.

3. Gotchas

World-crossing pointers. Kernel gets h_x, host derefs d_x — both type-check (5.3's opening). The h_/d_ convention + up/down methods are the whole defense; UVA making some crossings "work" on some systems makes discipline MORE necessary, not less.
Elements where bytes belong. cudaMemcpy(d, h, n, …) copies n BYTES: a quarter of your floats, three-quarters ghosts. n * sizeof *p, tattooed since 3.5.
cudaMalloc in hot loops. Each call syncs and taxes (~100+ µs — 3.5 §1's GPU note). Allocate once, reuse (DeviceBuffer's lifetime = the loop's scope), or cudaMallocAsync pools when dynamism is real.
Freeing the wrong world. free(d_x) or cudaFree(h_x): heap corruption or invalid-value error. Ownership tables (3.5 §4) now carry a WORLD column; RAII wrappers make it unrepresentable.
Timing async as if sync. CPU timer + cudaMemcpyAsync = measuring the enqueue (Ex.2's comment inverted). Events (5.9) for anything async; plain-blocking calls are the only CPU-timable ones.
Managed-memory benchmarks with cold pages. First-touch migration inside the timed region — M1 L7's warmup rule catches yet another species (5.1 P3 listed it): prefetch or warm before timing.

Practice

1. Classify each call's blocking behavior and world: cudaMalloc; kernel launch; plain cudaMemcpy D2H; cudaMemcpyAsync H2D (pinned); cudaFree; cudaDeviceSynchronize. Which subset defines your timing-safe set for CPU clocks?
cudaMalloc: blocking-ish (syncs device on classic path) — host world allocT device. Launch: async, queues. Plain memcpy: BLOCKING + stream-ordered (the implicit sync). Async memcpy: returns immediately (pinned required for true async). cudaFree: synchronizing (another implicit sync — and why hot-loop frees hurt twice). deviceSync: the explicit full barrier. CPU-timable: only fully-blocking spans (plain memcpy round trips, or anything bracketed by deviceSync) — everything else needs events (5.9). Six calls, three behaviors, one table you'll consult weekly.
2. Extend DeviceBuffer with a from_host static factory and a to_vector() using 3.7's std::vector — write the signatures, note the ownership story of each, and why to_vector RETURNS by value without a performance sin (3.7's exact teaching).
static DeviceBuffer from_host(const std::vector<T>& h) { DeviceBuffer b(h.size()); b.up(h.data()); return b; } — return-by-move (3.7 P5's one-word answer: moves), no copy of the device allocation (move transfers the pointer, source nulled). std::vector<T> to_vector() const { std::vector<T> v(n); down(v.data()); return v; } — NRVO/move makes the return free; the D2H copy is the only real cost and it's explicit. Ownership: buffer owns device memory; vectors own host memory; .data() bridges as always (3.7 §vector). The harness is now ergonomic enough that the RIGHT way is also the SHORT way — the design goal of all infrastructure.
3. Predict the output: allocate d_x (no memset), launch square<<<...>>>(d_x, d_x, n) reading and writing the SAME uninitialized buffer, copy down, print y[0..3]. Then explain why the values differ between Colab sessions but often REPEAT within one session — and which two course lessons cover the mechanism.
Plausible garbage floats (or zeros!): uninitialized device memory holds whatever the previous tenant left (3.2's ghosts — the GPU heap recycles like 3.5 §1's freelists). Within-session repeats: the allocator hands back the same recycled block (3.5's use-after-free "stable until reused" physics — as an allocator behavior). Across sessions: different tenant history. Zeros are common on fresh allocations (driver scrubbing) — WHICH IS WHY tests that pass on fresh buffers and fail on reused ones exist: never rely on implicit zeros; cudaMemset or initialize (the M2 L8 fixture rule: known input patterns, always).
4. Your app uploads a 3 GB model once, then per request: 4 MB in, kernel, 1 MB out, 200 req/s. A new hire proposes converting everything to managed memory "to simplify". Write the three-line verdict using 4.6's audit + this lesson's ledger.
Audit: weights resident (never re-cross — managed adds risk of accidental host touches evicting hot pages); per-request 5 MB × 200 = 1 GB/s explicit, toll-fine at 400 crossings/s. Managed's value here: zero (phases are ALREADY explicit and clean); managed's risk: one stray host-side debug read triggers quiz 2's storm on 3 GB of weights. Verdict: keep explicit copies + pinned request buffers; managed stays in the prototype notebook. "Simplify" that adds silent failure modes isn't simpler — it's deferred complexity with interest (4.5 §4's closing line, applied).
5. The round-trip test passes but a saxpy test reads all-zeros for x. The launch used d_y for BOTH x and y arguments (copy-paste). Why did nothing crash, what did the kernel compute, and which checklist line (5.2 P7) should have caught it — plus the harness upgrade that catches argument-aliasing generically.
Both pointers valid-world, valid-size: no fault (aliasing is legal!). Kernel computed y = a·y + y = (a+1)·y — self-saxpy: well-defined here (each thread reads/writes only its own i — no race), just WRONG. Checklist line 9 (fixture verification) catches it: expected 4.0, got 6.0 everywhere — a constant-offset signature that screams "wrong operand" (fixture-failure signatures are diagnostic, 5.2 Ex.2's philosophy). Harness upgrade: kernels take const-correct pointers (3.3's contract makes x const float* — passing d_y still compiles as it's convertible... so the REAL catch is the fixture) + a debug assert that in/out spans don't overlap when the contract says they shouldn't (an address-range check — 3.4's span discipline, deployed).
6. Design the pinned-pool for 5.9's pipeline (4.6's ring, materialized): API (acquire/release), sizing (chunks × depth from Little's-law shopping — 4.2 P4/4.6), lifetime (who owns, when freed), and the failure policy when the pool is exhausted. Cite the arena you already built (3.5 P7).
struct PinnedPool { std::vector<void*> free_list; size_t chunk; ... void* acquire(); void release(void*); } — cudaMallocHost chunks at construction (N = pipeline depth 3 + margin 1, chunk = the transfer quantum: 4.6's worked example sized 4 × frame), destructor cudaFreeHost's all (RAII, 3.7). Exhaustion policy: BLOCK the producer (backpressure — the pipeline's natural governor) rather than allocate (pinning casually at runtime violates 4.6's gotcha) or drop (data loss needs opting into, loudly). It IS 3.5 P7's arena with cudaMallocHost as the backing store and release returning to the free list instead of reset-all — one design, third deployment (host arena, device pools via MallocAsync, now pinned staging). You're not learning new structures anymore; you're re-instantiating one.
7. Write the plumbing-fixture suite manifest for the course repo (runs before ANY kernel test, forever): round-trip exactness per dtype (which dtypes get exact vs budgeted?), size-boundary cases (0, 1, odd, 2³¹-adjacent), direction-typo tripwire, world-crossing negative tests (how do you TEST for a segfault politely?), and the async-read tripwire. Each with its lesson citation. (This suite ships in 5.11's repo as tests/test_plumbing.cu.)
Round-trip: float/int32/uint8 EXACT (copies are byte-moves — any diff is plumbing, not math; M1 L8's legitimate-equality case) on patterns {ramp i, bit-pattern 0xDEADBEEF-style, all-zeros} (3.4 Ex.2's recognizable-garbage doctrine). Sizes: n=0 (legal no-op — APIs must not crash: M2 L6's empty-input contracts), n=1, odd ns (alignment tails), and a mocked-large test of index WIDTH math (can't allocate 2³¹ floats on a T4 — test the FORMULA with size_t asserts instead: 5.2's gotcha). World-crossing: launch with a host pointer under compute-sanitizer as an expected-detection test (politeness = run in a child process / sanitizer harness so the suite survives its own negative case — 3.8's discipline of testing the alarms). Async tripwire: an Async D2H followed immediately by a host read must FAIL the pattern check (proving the suite would catch quiz 1b) then pass after event sync. The manifest's meta-rule, same as ever: the fixture suite tests the INSTRUMENTS before the instruments test the kernels — M2 L6's constitution, final ratification.
